01The flow, in three zones

Data lives almost entirely in the green zone. The amber zone is deliberately honest: the browser app adds no application-level encryption, only the browser/OS at rest and TLS on the wire. The hosted sync server stores task content as plaintext. Only the self-hosted Docker image encrypts task fields at rest (ADR 0016). Task content reaches the red zone only when a user opts in to cloud sync or wires up the MCP server. Two smaller flows need neither: the feedback form, which sends the user’s message and no task data, and a preconnect to the hosted sync server, which carries no task data.

03Privacy claims check

Each stated guarantee, marked against what the code actually does.

Local-first Confirmed

IndexedDB is the system of record. The entire create → validate → persist → read loop is local Dexie calls with zero fetch in the path. On a fresh install with no sign-in, task content never leaves the browser. Each page still preconnects to the hosted sync server, which sends no task data.

  • Persistence is db.tasks.add/put only — crud/create.ts:41
  • Reads via local live query — use-tasks.ts:18
  • Sync is off unless explicitly enabled — config/get-set.ts:77

No server-side storage of task content Confirmed with one caveat

The shipped app has zero Next.js server touchpoints — no Server Actions, no app/api route handlers, no middleware. output: 'export' makes a server runtime structurally impossible, and the build emits no server/edge functions. The Next.js app cannot store your content because it has no server runtime to store it on.

  • rg "use server" → 0 real hits; app/ holds 14 page, layout, global-error, and not-found files, no route.ts, no middleware.ts
  • Static export confirmed — next.config.ts:8
Caveat — the claim is scope-sensitive. When a user opts into cloud sync, full task content (title, notes, tags, subtasks) is stored as plaintext on the PocketBase backend at api.vinny.io (task-mapper.ts:54), and the MCP server reads/writes it there. That is server-side storage: opt-in, but real, on a server run by GSD’s developer, who has technical access to it (ADR 0016). The self-hosted Docker image encrypts task fields at rest instead. The about page now says no server receives your data by default.

No third-party trackers Confirmed

No Google Analytics/GTM, Plausible, Fathom, Vercel Analytics, Segment, PostHog, Mixpanel, Hotjar, or Pixel in source or dependencies. Fonts are self-hosted (no runtime Google Fonts). The CSP connect-src enforces this at the policy layer.

  • The hosted egress allowlist is 3 external origins: api.vinny.io, accounts.google.com, and github.com. See config/csp.cjs
  • Note: Sentry error telemetry was removed (ADR 0017). Errors now go to the local console only. Google, GitHub, and Apple are contacted only for OAuth sign-in. Sign-in opens the provider’s page as a navigation, which connect-src does not govern. None profile usage.

Formerly stated in-app: “End-to-end encrypted · zero-knowledge” Corrected in the app

The June 2026 review found the about page contradicted the code. The app’s copy has since been corrected. There is still no end-to-end encryption: content is plaintext in IndexedDB and plaintext-over-TLS to the server.

  • The cloud sync card now reads “on a server run by GSD’s developer. Sent over TLS, and other accounts can’t see your tasks.” See features-section.tsx
  • The privacy section now says signing in uploads your tasks to that server, and that connections use TLS. See privacy-section.tsx
  • The MCP config example lists only GSD_POCKETBASE_URL and GSD_AUTH_TOKEN. ENCRYPTION_PASSPHRASE is gone. See mcp-section.tsx
  • The Sentry path is gone (ADR 0017). lib/error-logger.ts writes to the local console only.

Runtime caveats. Zones are static-analysis truths; at runtime task content enters the red zone only by user action (enabling sync, configuring MCP). The amber zone puts “encrypted” in quotes because the browser app adds no encryption of its own. Browser/OS disk encryption and TLS still apply but are outside the app’s control. On gsd.vinny.dev the PocketBase backend is the hosted service at api.vinny.io, run by GSD’s developer. You can run your own with the Docker image under docker/.
