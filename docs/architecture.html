Architecture

GSD Task Manager

Next.js 16 PWA Offline-First IndexedDB PocketBase Sync

A privacy-first Eisenhower matrix task manager. All data lives locally in IndexedDB; cloud sync is opt-in to a self-hosted PocketBase instance. Built as a static-export PWA deployed to S3/CloudFront.

TL;DR
  1. All data lives in IndexedDB via Dexie (schema v17, 11 tables). The app is fully functional offline with zero infrastructure.
  2. Cloud sync is opt-in via self-hosted PocketBase. Last-write-wins conflict resolution with client_updated_at timestamps. SSE realtime for instant cross-device updates.
  3. Static export to S3/CloudFront with a three-cache service worker strategy. No SSR and no API routes.
  4. MCP server provides 20 AI tools for Claude Desktop integration. All writes support dry-run mode.
  5. Key risks: LWW data loss on concurrent edits, single EC2 instance for PocketBase, no automated backups.

Overview

GSD organizes tasks into an Eisenhower matrix using two boolean flags: urgent and important. The v9 UI (app version 9, ADR-0011) replaced a multi-view layout with a single-matrix shell, capture bar, and edit drawer.

Q1 — Do First

Urgent + Important. Crisis, deadlines, emergencies.

Q2 — Schedule

Not Urgent + Important. Planning, growth, prevention.

Q3 — Delegate

Urgent + Not Important. Interruptions, some meetings.

Q4 — Eliminate

Not Urgent + Not Important. Time wasters, busy work.

02

User Experience

The v9 architecture centers on a single-matrix view with progressive disclosure: a capture bar for fast entry, an edit drawer for detail, and keyboard shortcuts for power users.

Interaction Model

Capture Bar

Press n to focus. Type with ! (urgent), * (important), !! (both), #tag markers. Tab reaches the quadrant button, which cycles the quadrant. Enter to submit. Outside a text field, Shift+N opens the full drawer.

Edit Drawer

Slide-in panel over the matrix preserving spatial context. Supports title, description, quadrant picker, due-date presets, tags, subtasks, and dependencies.

Drag & Drop

@dnd-kit with an 8px pointer activation distance and a 250ms touch delay. Tasks dragged between quadrants with ghost overlay. Drop targets highlight with quadrant accent color.

Command Palette

Cmd+K (or Ctrl+K) opens cmdk-based palette for quick actions and task search. Mounted in AppShell on every route.

Navigation Architecture

Every route page except the OAuth callback shares the AppShell component providing a collapsible icon rail (desktop) or bottom tab bar (mobile), topbar with search, help drawer, and command palette.

Matrix → Saved → Review → Settings → About

Route groups: (matrix), (dashboard), (archive), (sync), plus standalone /settings, /about, /saved, /sweep, and /auth/callback. Review is the /dashboard route. Archive, sync history, and the weekly sweep have no rail item.

Accessibility

What works well
ARIA landmarks on navigation, aria-pressed on toggles, aria-current="page" on active nav, Radix Dialog with focus trapping for help drawer, focus-visible rings, 44x44px mobile touch targets, prefers-reduced-motion support. The edit drawer is a hand-rolled role="dialog" panel with aria-modal and a focus trap (use-dialog-focus.ts).

Technical Architecture

GSD is a fully client-side application. Interactive components use "use client". The root layout and a few pages have no directive and prerender at build time. There is no runtime server, so the static export needs no SSR infrastructure.

Module Structure

lib/

About 60 top-level files. Data layer core: db.ts and db-migrations.ts (Dexie schema), tasks/ (CRUD, import and export), schema.ts (Zod), use-tasks.ts (live queries), quadrants.ts (Eisenhower logic). Subdirectories include analytics/, notifications/, sync/.

lib/sync/

30 source files: 26 at the top level and 4 in config/. Modular sync system: pocketbase-client.ts, pb-sync-engine.ts (full sync), pb-push.ts, pb-pull.ts, pb-realtime.ts (SSE), pb-auth.ts (OAuth), task-mapper.ts, sync-coordinator.ts, health-monitor.ts, queue.ts, retry-manager.ts.

components/

Domain-specific groups: matrix-simplified/ (v9 shell), task-card/ (composable card), sync/, settings/, settings-page/, dashboard/, command-palette/.

packages/mcp-server/

Standalone workspace. 7 read tools, 5 write tools (with dry-run), 5 analytics tools, 3 system tools. Stdio transport, TTL cache. It reads tasks from PocketBase, so it needs cloud sync.

Data Flow

Write path:

User Action → Zod Validation → Dexie Transaction → IndexedDB → PocketBase Push (async, optional)

Read path:

IndexedDB → useLiveQuery → React Component → Auto Re-render

Sync path:

sync-coordinator → pb-push (100ms throttle) ↔ PocketBase API ↔ pb-pull (LWW) → Dexie

Persistence & Sync

All data lives locally in IndexedDB via Dexie. Cloud sync is an opt-in layer that pushes and pulls to a self-hosted PocketBase instance using last-write-wins conflict resolution.

Task Data Model

Tasks are validated by Zod schemas at all data boundaries. The quadrant is derived from urgent + important booleans via resolveQuadrantId(). The cards below show the main fields. lib/schema.ts holds the full list.

Core Fields

id, title, description, urgent, important, quadrant, completed, completedAt, dueDate, createdAt, updatedAt

Nested Structures

subtasks[] (id/title/completed), tags[], dependencies[] (task IDs), timeEntries[] (startedAt/endedAt/notes)

Recurrence & Snooze

recurrence pattern, snoozedUntil. Completed recurring tasks auto-create the next instance.

Sync Protocol

Last-Write-Wins (LWW)
Conflict resolution uses client_updated_at timestamps. A remote record wins only if its timestamp is strictly newer. One exception: the one-time full pull that backfills a newly synced field also accepts a tie (ADR-0019). Pull cursors overlap by 30 seconds to catch boundary records. A remote timestamp more than 5 minutes ahead of now is clamped to that ceiling, which limits clock drift.
OperationMechanismSafeguards
PushDrain syncQueue sequentially, 100ms throttlePer-row remote lookup, LWW guard before write, session check, abort on HTTP 429
PullFetch by owner + client_updated_at >= cursor30s overlap window, archive and Trash tombstones, preserve device-local fields, skip invalid records
RealtimePocketBase SSE subscribe('*')Echo filtering via device_id, owner validation, Zod schema check
Delete ReconciliationCompare remote index vs local after pullPending-queue check, fetchSucceeded guard, session confirmation. A task whose queue rows are all retry-exhausted goes to Trash, not deleted outright
Field MappingcamelCase (local) ↔ snake_case (PocketBase)Zod validation of every pulled record (pbTaskRecordSchema)

Import / Export

Export

Strict validation — taskRecordSchema.strict() rejects unknown fields. Writes a versioned envelope (2.2.0, ADR-0014) with live, archived, and trashed tasks, smart views, and settings. Skips corrupt tasks with warning.

Import

Lenient validation — .strip() silently drops unknown fields (e.g., legacy vectorClock). Two modes: replace (clear + replace) or merge (regenerate conflicting IDs). Safety limits: 10K task records across live, archive, and Trash, 10MB max.

Single Points of Failure

RiskImpactMitigation
PocketBase on single EC2 All synced users lose multi-device capability None documented. No failover, no multi-region.
No automated PocketBase backup Disk failure loses all synced data permanently SQLite on EC2 with no backup scripts or S3 snapshots.
Hand-written service worker A bug silently breaks offline for all users public/sw.js is hand-written. Its cache routing comes from lib/sw-cache-logic.ts. public/sw-cache-logic.js is generated from that file, and a test fails when the copy drifts.
LWW data loss Simultaneous edits to different fields silently loses one set Acknowledged in ADR-0003. No conflict visibility for users.

Security Surface

Auth tokens in localStorage
PocketBase auth tokens live in localStorage via the SDK’s authStore. Any XSS vulnerability grants full read/write access to all synced task data. The hosted service (the project’s PocketBase at api.vinny.io) does not encrypt task content at rest (ADR-0016).
MCP server bearer token
GSD_AUTH_TOKEN is a 30-day bearer token visible in shell history, process listings, and Claude Desktop config files. The MCP README covers expiry and renewal, and get_token_status reports the time left.

The Hard Questions

  • If api.vinny.io (the PocketBase host) goes down for 48 hours, what happens? What’s the user experience? What’s the data recovery story? Is there even a backup?
  • The app markets itself as “privacy-first” but stores plaintext tasks on a server with localStorage tokens and no encryption. What is the actual threat model?
  • 30 files and about 5,500 lines of sync code for an optional feature on a personal task app — is this proportional to the value it delivers?
  • MCP server requires cloud sync to function. It cannot access local-only IndexedDB data. Does this limit the “privacy-first” story for AI-powered task management?

Architecture Decision Records

Key architectural decisions are captured in ADRs under docs/adr/. Each documents the context, decision, consequences, and alternatives considered.

ADR-0001

Client-Side Only IndexedDB — All data stored locally. No server required for core functionality.

ADR-0002

PocketBase Cloud Sync — Self-hosted PocketBase for opt-in multi-device sync.

ADR-0003

Last-Write-Wins Conflict Resolution — Whole-record LWW using client_updated_at timestamps.

ADR-0004

PWA Architecture — Progressive Web App with service worker and offline support.

ADR-0005

MCP Server Integration — 20-tool Claude Desktop integration via stdio JSON-RPC.

ADR-0006

Analytics Modular Design — Modular metrics, streaks, tags, and trends system.

ADR-0007

Notification System Design — Modular notification display, permissions, settings, and badges.

ADR-0008

BFS Circular Dependency Detection — Breadth-first search to prevent dependency cycles.

ADR-0009

Smart Views System — Custom filtered views (removed in v9, back as an opt-in strip).

ADR-0010

Agent Discovery Surface — Static discovery metadata for AI agents: /.well-known files, Link headers, and an in-page WebMCP tool.

ADR-0011

v9 Single Matrix Refactor — Removed about 30 files for a single-matrix shell + capture bar.

ADR-0012

SW Multi-Cache Strategy — Three purpose-specific caches reducing post-deploy re-download by ~95%.

ADR-0013

Archived Tasks Conditional Tombstone. An archived id blocks re-creation unless the remote edit is newer.

ADR-0014

Versioned Backup Envelope. JSON backups carry a version, plus archive, Trash, and settings.

ADR-0015

Trash With Retention. Deletes move to a per-device Trash for 30 days.

ADR-0016

Hosted Sync Defers Field Encryption. The hosted service stores task content unencrypted. The PocketBase hooks in the self-host Docker image can encrypt it.

ADR-0017

Remove Sentry Telemetry. Sentry error telemetry is gone from the app.

ADR-0018

Saved Task Placement. Saved holds bookmarks and short notes outside the matrix. It is a placement independent of quadrant.

ADR-0019

Pull Contract Version Backfill. The pull contract is a version number for the set of synced fields. A bump pulls everything once to backfill a new field.

ADR-0020

Pull Contract 4, Top Three. Pull contract version 4 syncs each task’s top three pick (focus_date, focus_rank).
