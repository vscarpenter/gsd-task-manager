## For your review, by priority

### P1: data loss, silent failure, or a broken pipeline

1. **Docker image publish fails intermittently** (verified from CI logs). It failed 4 of the last 22 completed runs, including `20dc641`. The build couldn't fetch Newsreader through `next/font/google` on the arm64 (QEMU) leg, and #713 changed no build input. Re-run the failed job. Then vendor the font with `next/font/local`, which also unblocks builds in cloud sandboxes. Build the static stage once with `--platform=$BUILDPLATFORM` and add `timeout-minutes` (TOOL-21).
2. **A revoked or rejected token reads as an empty account** (reported independently by two reviewers: MCP-1, SYNC-3, SYNC-10). The web's own comment at `lib/sync/pb-sync-helpers.ts:196-198` says PocketBase lists `tasks` as 200 with no items for such a token.
   - MCP: `list_tasks` returns `[]`, and update, complete, and delete answer "Task not found".
   - Web: push dequeues deletes as "pushed" that never reach the server, and the user is never asked to sign in again.
   - Fix: confirm the session before trusting an empty listing or a 404, in both clients. Run `pb-sync-reviewer` and `verify-sync-session` on the fix.
3. **Auto-sync stops for good after five failed syncs** (reported, SYNC-1). The gate survives a reload, nothing schedules `nextRetryAt`, and the button says "Retrying in 300s…". One always-failing row trips it. Decide whether to drop the gate (the backoff already caps at 300 s) or to show a paused state with a resume action.
4. **A multi-page pull can skip a record permanently** (reported and reproduced by the reviewer, SYNC-2). The pull pages by offset over `client_updated_at`, which edits change. Switch to keyset paging on `(client_updated_at, id)`. It is related to `WEB-PULL-CURSOR-SKIP`.
5. **Fresh self-hosted servers enforce no field limits** (reported, SYNC-8, based on the repo's own note that PocketBase 0.40.4 ignores `options` blocks). The three schema scripts put validators there, and the update script never adds `saved_at`. Before moving the validators, note that the planned `time_entries` limit is smaller than what the client allows.
6. **Background reminders don't exist** (reported, UI-1; certain from code). `public/sw.js` `checkAndNotifyTasks()` only clears the badge, yet Settings and Help promise background checks. Either implement it or remove the registration and the copy.
7. **Deploy marks unhashed files immutable for a year** (reported, TOOL-1, likely). This covers RSC payloads, `manifest.json`, and icons. Check with `curl -sI https://gsd.vinny.dev/about/__next._tree.txt`. The Caddyfile has the mirror problem (TOOL-14).
8. **The self-host container stays Up when PocketBase crashes** (reported, TOOL-3). `wait "$PB_PID" "$CADDY_PID"` waits for both processes.
9. **`.agents/skills` still holds the retired builder and night-shift routines** (reported, TOOL-2; certain from the text). They claim issues, build, push, and check out PR branches. Delete `source-command-build-next` and `source-command-triage-prs`. The `open-knowledge` skill routes every markdown edit through MCP tools that don't exist (TOOL-9).
10. **The PocketBase admin scripts default to production** (reported, TOOL-5). Use `: "${PB_URL:?set PB_URL explicitly}"`.
11. **The hooks in `.claude/settings.json` can fail open or block silently** (reported, TOOL-6, 7, 35, 40). Hook paths are relative, so a `cd packages/mcp-server` breaks them; my own shell landed there during this session. Stop-hook errors go to stdout, which Claude doesn't see on exit 2. I left these alone because they gate the agent itself.
12. **Tests are never typechecked** (verified). `tsconfig.vitest.json` is referenced by nothing and inherits `exclude: ["tests"]`, and `vitest.d.ts` loads jest-dom's Jest types (TEST-8). With jest-dom's Vitest types, the probe found 208 real errors in 67 root test files (fixture drift) and 60 in 12 MCP test files (MCP-14). Add a `typecheck:tests` gate after a typed fixture factory (TEST-14).
13. **CI doesn't require e2e, MCP coverage, or the PocketBase system test** (reported, TOOL-12). Confirm with `gh api repos/vscarpenter/gsd-task-manager/rulesets`.
14. **`bun run deploy` ships a local build outside Gate 2** (verified). README now says so. Decide whether to keep it as a labelled break-glass that refuses a dirty tree or a non-tag HEAD, or to delete it (TOOL-4).
15. **Releases.** The fixes above are user-visible, so web needs a version bump (production serves 14.8.0). MCP's Unreleased section is ready for 1.4.2.
